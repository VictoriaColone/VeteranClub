# 星曜电竞 · 俱乐部前端

统一用户端同时支持 H5 与微信小程序，员工使用 PC 管理后台。用户端共用一套 uni-app 页面和业务模型。移动端使用 **uni-app + Vue 3 + TypeScript + uni-ui + Pinia**；管理后台使用 **Vue 3 + TypeScript + Element Plus + Pinia**。所有业务接口和数据由可替换的模拟服务实现，当前无需后端、数据库、微信账号和支付资质即可运行。

“星曜电竞”是演示品牌，可在管理员「俱乐部设置」修改。所有人物、订单、收入均为虚构样例。

## 启动

要求 Node.js 20+（已用 Node.js 22 验证），npm 10+。

```bash
npm ci
npm run dev
```

- 统一入口：`http://127.0.0.1:4173/`
- 下单用户／成员 H5：`http://127.0.0.1:4173/mobile/`
- 员工后台：`http://127.0.0.1:4173/admin/`

统一入口进入用户 H5；员工通过独立的 `/admin/` 地址访问后台。用户 H5 不提供后台入口。建议始终从 4173 端口访问两个应用，以共享同源模拟数据。单独的 5174、5175 端口仅供单应用开发，浏览器会将它们的数据隔离。

生产构建与本地预览：

```bash
npm run check
npm test
npm run build
npm run preview
```

`dist/mobile/` 和 `dist/admin/` 可整体交给 Nginx 静态托管。**这不是 Spring Boot 服务端实现**；服务端在本阶段按需求全部模拟。

## 演示路径

1. 发现页点击「快速下单」：选择三角洲、无畏契约或英雄联盟，选择组队／护航，默认不指定服务成员。普通用户无需考核即可下单。
2. 组队按 1～8 小时时长计价；护航填写任务项和整单金额，模拟任务默认“100w纯带出”。确认模拟支付后，不指定成员的订单进入公共单大厅。
3. 右下角「＋」仅在有有效资格时显示，菜单只展示已获资格类型的商品发布和商品管理；资格申请统一从「我的」进入。通过考核后可发布组队或护航商品，填写游戏、标题、说明和单价／任务项。商品与订单独立，发布商品不产生收付款。
4. 发现页浏览商品，点击「立即下单」会指定该商品的发布者，价格和任务采用服务端商品快照；指定订单只进入对应成员的「邀请我的」，不进入公共大厅。
5. 接单页顶部「立即抢单」打开筛选弹窗，确认后接取最早的可接公共单；下方只展示未指定成员的待接订单。接口检查资格、在线状态、自接单及占单限制。
6. 护航负责人可在开始前添加副手，开始后锁定名单。任务完成后提交验收；组队按时长完成（演示可点击「模拟走满时长」）。下单用户确认后，后台按成员份额生成独立结算批次。
7. 入驻流程：申请 → 资料审核 → 专项考核 → 录入至少 60 分后开通对应类型、游戏的商品发布与接单资格。两类独立，普通购买服务不受资格限制。
8. 「我的商品」可上下架个人商品；订单售后仍支持全额／部分模拟退款，待审核时冻结履约和结算。

初始数据包含 3 款游戏（三角洲、无畏契约、英雄联盟）、10 个用户档案和 20 笔不同状态订单。体验账号覆盖四种状态：「林序」无资格、「小屿」仅组队、「凛」仅护航、「岚」两类都有；可在顶部“体验账号”切换。副手可选择「远山」。后台员工身份切换在员工卡片或头像处。

## 模拟服务约定

- 默认直接调用浏览器内的 Mock Transport，不实际发送 HTTP 请求。接口路径、请求与响应类型在共享模块统一定义。
- 主业务数据键为 `stellar-club:database:v1`。H5 使用 LocalStorage，同一浏览器同源标签页共享；微信小程序使用 `uni.getStorageSync/setStorageSync` 原生存储。H5、小程序和不同设备的数据各自独立，只有接入同一真实后端后才能跨端同步。
- 用户端可见时每 10 秒刷新，切后台暂停计时器，回前台刷新订单与计时；后台每 12 秒刷新，并监听跨标签页存储变化。
- 支持 Web Locks 的浏览器会串行处理同源模拟请求；这只是演示一致性机制。真实接单并发控制必须由服务端数据库事务实现。
- 数据更新失败不会自动转入真实付款。页面明确标注模拟登录、支付、退款和结算。
- 登录为演示身份签发模拟会话，不代表生产安全认证。默认自动登录以便快速体验；真实登录需要换成微信授权及服务端会话流程。
- 欠缺真实手机号、真实身份认证、短信、图片上传、在线客服及支付渠道接入。历史评分与订单数是固定档案样例。
- 为方便演示，下单用户确认完成后即可生成结算批次，**未实现真实业务的售后等待期、税务处理、银行付款与渠道对账**。
- 结算后退款需真实后台另行设计结算调整流程，当前演示对此入口作限制。
- 管理员「俱乐部设置」可重置模拟数据；保留当前演示会话。

## H5 与微信小程序

复制对应应用 `.env.example` 为 `.env.local`，设置 `VITE_API_MODE=http` 和 API 地址即可改用 HTTP Transport。但登录的 `mock-login` 端点仅用于演示，接真实服务时必须替换登录入口，并由后端完成身份、权限、支付回调与事务处理。

H5 与小程序登录、支付需要分别接入。内部 `userId` 独立于 `appid + openid`；不能直接使用公众号 OpenID 作为小程序 OpenID。

用户端现已可分别构建 H5 和微信小程序，订单、商品、资格、护航协作、售后及钱包共用业务实现。微信端适配胶囊导航、安全区、弹窗滚动、原生存储、前后台生命周期与首页分享。默认仍是模拟账号与模拟支付。

```bash
npm run dev:mp-weixin    # 微信开发版，持续编译
npm run build:mp-weixin  # 微信发布构建 + 产物完整性/主包体积检查
npm run build:all        # H5、PC 后台和微信小程序一起构建
```

微信开发者工具导入目录：`apps/mobile/dist/build/mp-weixin`（开发模式为 `dist/dev/mp-weixin`）。没有 AppID 时生成 `touristappid` 游客模拟项目；已注册后，在 `apps/mobile/.env.local` 设置公开的 `WEIXIN_APPID=wx...` 并重新构建。不把 AppSecret、支付密钥或证书放进前端。

完整导入、联调和上线步骤见 [微信小程序说明](docs/WEIXIN.md)。已通过编译与代码/产物检查，尚未完成微信开发者工具及真机验收，也未上传微信或接入真实登录支付。

## 协作分账规则

护航净报酬 = （实付金额 − 已批准退款金额）×（1 − 下单时的平台服务费比例），向下取整到分。负责人和所有副手同权均分；无法整除到分时，按名单顺序依次补一分，确保份额之和等于净报酬且相差不超过一分。开始服务后锁定名单。按成员记录结算批次；任一份额进入结算后，整单不再允许发起退款，需后续真实后台处理结算调整。

现有 v1 浏览器数据会迁移保留订单、会话及结算记录。旧订单归为组队时长单；旧版已认证档案转换为两类演示资格。

商品发布与接单采用同一份对应类型、游戏的考核授权。新用户默认两类均无商品发布与接单权限；待审核、考核中、拒绝均不授予权限。通过组队考核不会开放护航权限，反之亦然。页面入口与模拟接口均校验；普通用户无需考核即可购买服务和快速下单。

组队与护航考核互不依赖，允许任意一种先通过；未开通的另一类型仍可独立提交申请，申请中或未通过不会影响已有类型的权限。体验账号描述依据实际资格动态显示；已有浏览器数据升级时补充单资格样例，保留原订单、审核记录与会话。

当前游戏目录仅开放三角洲、无畏契约和英雄联盟。组队订单统一按小时计时；护航订单发布必须提交非空字符串任务项，样例任务与下单演示默认“100w纯带出”，可修改。旧版模拟配置中的王者荣耀、和平精英映射到三角洲，并在关联订单动态中记录转换，保留金额、状态、成员及结算记录。用户自定义任务保留。

无任一有效接单资格时，隐藏发现页“＋”与底部“接单”标签，资格申请入口保留在“我的”；取得组队或护航任一类型的有效游戏资格后显示。当前停留在接单页而资格被撤销时自动返回发现页。发现页的“＋”仅用于已有资格类型的商品发布和商品管理，不提供资格申请；主入口为快速下单。商品数据与订单分开持久化，历史数据升级自动补充商品目录，不重置订单与结算。

用户端不设独立“报酬”标签；从“我的 → 全部订单”查看订单，参与订单显示本人净报酬与结算进度，详情包含个人份额、结算批次及模拟付款时间。“我的”统计可直接进入全部、进行中、已完成订单，切换账号或重新进入全部订单会重置旧筛选。
