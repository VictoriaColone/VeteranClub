# 星曜电竞 · 俱乐部前端

老板／打手移动端和员工 PC 管理后台。移动端使用 **uni-app + Vue 3 + TypeScript + uni-ui + Pinia**；管理后台使用 **Vue 3 + TypeScript + Element Plus + Pinia**。所有业务接口和数据由可替换的模拟服务实现，当前无需后端、数据库、微信账号和支付资质即可运行。

“星曜电竞”是演示品牌，可在管理员「俱乐部设置」修改。所有人物、订单、收入均为虚构样例。

## 在线体验与分享

- 移动端：<https://stellar-club-h5.dear-goose-6136.chatgpt.site/mobile/>
- 管理后台：<https://stellar-club-h5.dear-goose-6136.chatgpt.site/admin/>

Demo 已按项目所有者要求设置为公开体验，任何拿到链接的人都可访问，无需 ChatGPT 登录。每个人使用各自浏览器内的模拟数据，不会跨设备同步；模拟登录、付款和结算不连接真实业务。

两端共用 `shared/theme.css` 的颜色、圆角、间距和状态语义：深色背景、荧光绿主操作、紫色辅助。移动端以搜索、游戏筛选、快速下单为主；后台首页提供待派单、售后和结算快捷入口。

## 启动

要求 Node.js 20+（已用 Node.js 22 验证），npm 10+。

```bash
npm ci
npm run dev
```

- 统一入口：`http://127.0.0.1:4173/`
- 老板／打手 H5：`http://127.0.0.1:4173/mobile/`
- 员工后台：`http://127.0.0.1:4173/admin/`

统一入口在桌面跳至后台，在手机跳至 H5。建议始终从 4173 端口访问两个应用，以共享同源模拟数据。单独的 5174、5175 端口仅供单应用开发，浏览器会将它们的数据隔离。

生产构建与本地预览：

```bash
npm run check
npm test
npm run build
npm run preview
```

`dist/mobile/` 和 `dist/admin/` 可整体交给 Nginx 静态托管。**这不是 Spring Boot 服务端实现**；服务端在本阶段按需求全部模拟。

## 演示路径

1. 打开移动端，默认为老板「林序」，点击「邀请一起玩」或「快速下单」。选择游戏、区服、1～8 小时时长，提交订单。
2. 点击「确认模拟支付」，订单进入待接单。不发生真实扣款。
3. 点击顶部「老板端」，切换为打手「岚」。在接单大厅接取匹配的无畏契约订单；也可在后台为岚派单。
4. 在打手「订单」中开始服务、填写服务记录并提交完成。
5. 切回老板，在待确认订单点击确认完成。
6. 打开管理后台「报酬结算」，生成批次、确认模拟付款。打手「报酬」页随之更新。
7. 退款演示：老板在已支付且尚未进入结算批次的订单申请全额或部分退款；财务或管理员在「退款售后」审核。待审时暂停履约和结算，批准后按净额更新报酬。

初始数据包含 4 款游戏、6 名打手、2 位老板和 20 笔不同状态订单。打手「岚」可直接接取大厅中的匹配订单。后台角色切换在左下角员工卡片或右上角头像。

## 模拟服务约定

- 默认直接调用浏览器内的 Mock Transport，不实际发送 HTTP 请求。接口路径、请求与响应类型在共享模块统一定义。
- 主业务数据保存在 LocalStorage 的 `stellar-club:database:v1` 中；同一浏览器、同一源下的不同标签页共享。不同设备、不同浏览器、不同域名或端口不共享。
- H5 每 10 秒刷新，后台每 12 秒刷新；后台也监听跨标签页存储变化，均有手动刷新入口。
- 支持 Web Locks 的浏览器会串行处理同源模拟请求；这只是演示一致性机制。真实接单并发控制必须由服务端数据库事务实现。
- 数据更新失败不会自动转入真实付款。页面明确标注模拟登录、支付、退款和结算。
- 登录为演示身份签发模拟会话，不代表生产安全认证。默认自动登录以便快速体验；真实登录需要换成微信授权及服务端会话流程。
- 欠缺真实手机号、真实身份认证、短信、图片上传、在线客服及支付渠道接入。历史评分与订单数是固定档案样例。
- 为方便演示，老板确认完成后即可生成结算批次，**未实现真实业务的售后等待期、税务处理、银行付款与渠道对账**。
- 结算后退款需真实后台另行设计结算调整流程，当前演示对此入口作限制。
- 管理员「俱乐部设置」可重置模拟数据；保留当前演示会话。

## 后端与小程序接入

复制对应应用 `.env.example` 为 `.env.local`，设置 `VITE_API_MODE=http` 和 API 地址即可改用 HTTP Transport。但登录的 `mock-login` 端点仅用于演示，接真实服务时必须替换登录入口，并由后端完成身份、权限、支付回调与事务处理。

H5 与小程序登录、支付需要分别接入。内部 `userId` 独立于 `appid + openid`；不能直接使用公众号 OpenID 作为小程序 OpenID。

保留了 `npm run build:mp-weixin` 编译入口和 uni.request 适配器。小程序 AppID 暂空，需要后续配置合法域名、真实小程序授权和支付调起，并通过微信开发者工具及真机验收。当前交付范围为 H5；不宣称小程序已上线或已验证。
