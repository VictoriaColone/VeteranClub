# 星曜电竞 · 俱乐部前端

统一用户移动端和员工 PC 管理后台。移动端使用 **uni-app + Vue 3 + TypeScript + uni-ui + Pinia**；管理后台使用 **Vue 3 + TypeScript + Element Plus + Pinia**。所有业务接口和数据由可替换的模拟服务实现，当前无需后端、数据库、微信账号和支付资质即可运行。

“星曜电竞”是演示品牌，可在管理员「俱乐部设置」修改。所有人物、订单、收入均为虚构样例。

## 在线体验与分享

- 移动端：<https://stellar-club-h5.dear-goose-6136.chatgpt.site/mobile/>
- 管理后台：<https://stellar-club-h5.dear-goose-6136.chatgpt.site/admin/>

Demo 已按项目所有者要求设置为公开体验，任何拿到链接的人都可访问，无需 ChatGPT 登录。每个人使用各自浏览器内的模拟数据，不会跨设备同步；模拟登录、付款和结算不连接真实业务。

两端共用 `shared/theme.css` 的颜色、圆角、间距和状态语义：深色背景、荧光绿主操作、紫色辅助。移动端以搜索、游戏筛选、快速下单为主；后台首页提供待派单、售后和结算快捷入口。

## 启动

要求 Node.js 20+（已用 Node.js 22 验证），npm 10+。

```bash
npm ci
npm run dev
```

- 统一入口：`http://127.0.0.1:4173/`
- 下单用户／成员 H5：`http://127.0.0.1:4173/mobile/`
- 员工后台：`http://127.0.0.1:4173/admin/`

统一入口进入用户 H5；员工通过独立的 `/admin/` 地址访问后台。用户 H5 不提供后台入口。建议始终从 4173 端口访问两个应用，以共享同源模拟数据。单独的 5174、5175 端口仅供单应用开发，浏览器会将它们的数据隔离。

生产构建与本地预览：

```bash
npm run check
npm test
npm run build
npm run preview
```

`dist/mobile/` 和 `dist/admin/` 可整体交给 Nginx 静态托管。**这不是 Spring Boot 服务端实现**；服务端在本阶段按需求全部模拟。

## 演示路径

1. 打开移动端，默认体验账号为「林序」。先在“我的”提交申请、由后台完成资料审核和专项考核，或切换到已认证体验账号。新用户默认无两类订单的发单、接单权限，需分别申请组队和护航考核。
2. 通过对应考核后选择「组队订单」：选择游戏、区服、1～8 小时时长；或选择「护航订单」：填写指定任务、验收标准与整单金额。
3. 确认模拟支付后，使用顶部「体验账号」切到「岚」，在「接单」页接取订单。岚同样可以发布自己的订单。
4. 护航订单接取后可添加副手「远山」，开始服务后名单锁定。提交完成时需确认指定任务已达成并填写验收记录。
5. 组队订单需要服务够约定时长，演示可由负责人点击「模拟走满时长」，再提交完成记录。
6. 切回下单账号确认完成。后台「报酬结算」按协作成员生成独立批次并模拟付款；每位成员看到自己的份额。
7. 入驻演示：林序在「我的」分别申请组队或护航资格，选择游戏并填写经验；后台「入驻考核」先审核资料、安排考核，再录入至少 60 分成绩才能开通所申请方向与游戏的发单与接单资格。
8. 退款演示：下单用户申请全额或部分退款；财务或管理员审核。待审时暂停履约、协作名单变更和结算，批准后按净额重算分账。

初始数据包含 4 款游戏、8 个用户档案和 20 笔不同状态订单。「岚」和「远山」是已认证的体验账号，用户「林序」默认无资格，可体验两类独立申请流程。后台员工身份切换在员工卡片或头像处。

## 模拟服务约定

- 默认直接调用浏览器内的 Mock Transport，不实际发送 HTTP 请求。接口路径、请求与响应类型在共享模块统一定义。
- 主业务数据保存在 LocalStorage 的 `stellar-club:database:v1` 中；同一浏览器、同一源下的不同标签页共享。不同设备、不同浏览器、不同域名或端口不共享。
- H5 每 10 秒刷新，后台每 12 秒刷新；后台也监听跨标签页存储变化，均有手动刷新入口。
- 支持 Web Locks 的浏览器会串行处理同源模拟请求；这只是演示一致性机制。真实接单并发控制必须由服务端数据库事务实现。
- 数据更新失败不会自动转入真实付款。页面明确标注模拟登录、支付、退款和结算。
- 登录为演示身份签发模拟会话，不代表生产安全认证。默认自动登录以便快速体验；真实登录需要换成微信授权及服务端会话流程。
- 欠缺真实手机号、真实身份认证、短信、图片上传、在线客服及支付渠道接入。历史评分与订单数是固定档案样例。
- 为方便演示，下单用户确认完成后即可生成结算批次，**未实现真实业务的售后等待期、税务处理、银行付款与渠道对账**。
- 结算后退款需真实后台另行设计结算调整流程，当前演示对此入口作限制。
- 管理员「俱乐部设置」可重置模拟数据；保留当前演示会话。

## 后端与小程序接入

复制对应应用 `.env.example` 为 `.env.local`，设置 `VITE_API_MODE=http` 和 API 地址即可改用 HTTP Transport。但登录的 `mock-login` 端点仅用于演示，接真实服务时必须替换登录入口，并由后端完成身份、权限、支付回调与事务处理。

H5 与小程序登录、支付需要分别接入。内部 `userId` 独立于 `appid + openid`；不能直接使用公众号 OpenID 作为小程序 OpenID。

保留了 `npm run build:mp-weixin` 编译入口和 uni.request 适配器。小程序 AppID 暂空，需要后续配置合法域名、真实小程序授权和支付调起，并通过微信开发者工具及真机验收。当前交付范围为 H5；不宣称小程序已上线或已验证。

## 协作分账规则

护航净报酬 = （实付金额 − 已批准退款金额）×（1 − 下单时的平台服务费比例），向下取整到分。负责人和所有副手同权均分；无法整除到分时，按名单顺序依次补一分，确保份额之和等于净报酬且相差不超过一分。开始服务后锁定名单。按成员记录结算批次；任一份额进入结算后，整单不再允许发起退款，需后续真实后台处理结算调整。

现有 v1 浏览器数据会迁移保留订单、会话及结算记录。旧订单归为组队时长单；旧版已认证档案转换为两类演示资格。

发单与接单采用同一份对应类型、游戏的考核授权。新用户默认两类均无权限；待审核、考核中、拒绝均不授予权限。通过组队考核不会开放护航权限，反之亦然。页面入口与模拟接口均校验，已存在的订单仍可查看与处理售后。
