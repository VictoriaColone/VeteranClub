# 诺曼部落 Norman Club

统一用户端同时支持 H5 与微信小程序，员工使用 PC 管理后台。用户端共用一套 uni-app 页面和业务模型。移动端使用 **uni-app + Vue 3 + TypeScript + uni-ui + Pinia**；管理后台使用 **Vue 3 + TypeScript + Element Plus + Pinia**。项目同时提供浏览器内 Mock 演示和真实服务端：**Java 21 + Spring Boot + Spring Security + MyBatis + MySQL 8.4 + Flyway**。真实接口版已接入用户短信登录、员工密码＋TOTP 登录及数据库业务；支付渠道保持关闭，预留后续 SDK 接口。

**当前已暂缓登录接入，默认使用免登录演示模式。** 用户端自动进入体验账号，后台自动进入模拟管理员；不需要手机号验证码、密码或身份验证器。本机当前入口为 `http://127.0.0.1:4180/mobile/` 和 `/admin/`。演示数据保存在当前浏览器，收付款均为模拟；此前的真实数据库单独保留。

重新启动当前演示入口：

```bash
npm run demo              # 构建免登录演示，并在 4180 启动预览
```

服务端认证代码保留，等物料齐备后再恢复接入。真实服务启动、数据库、账号、短信与部署说明见 [服务端说明](docs/SERVER.md)，防注入、鉴权、限流与 IP 封禁见 [安全说明](docs/SECURITY.md)。`build:http` / `preview:http` 是主动启用真实认证的联调命令，当前无需运行，且不能与 4180 的演示预览同时启动。

需要在服务器检查真实 API、共享数据库和完整流程时，使用独立的[内部验收环境](docs/ACCEPTANCE.md)：保留免登录体验身份、模拟收付款，通过 SSH 隧道私人访问；验收入口不会进入普通正式 JAR。

服务器现有 MySQL 的网页查表、SQL 查询、编辑与导入导出使用 [Adminer 数据库可视化管理](docs/DATABASE-UI.md)，无需另购数据库服务。

平台名称为“诺曼部落 Norman Club”。浏览器 Demo 内的人物、订单、收入为虚构样例；真实数据库不自动灌入这些数据。

## 演示路径

1. 发现页点击「快速邀请」：选择三角洲、无畏契约或英雄联盟，选择组队／护航，默认不指定服务成员。普通用户无需考核即可下单。
2. 组队按 1～8 小时时长计价；护航填写任务项和整单金额，模拟任务默认“100w纯带出”。确认模拟支付后，不指定成员的订单进入公共单大厅。
3. 右下角「＋」仅在有有效资格时显示，菜单只展示已获资格类型的商品发布和商品管理；资格申请统一从「我的」进入。通过考核后可发布组队或护航商品，填写游戏、标题、说明和单价／任务项。商品与订单独立，发布商品不产生收付款。
4. 发现页浏览商品，点击「立即下单」会指定该商品的发布者，价格和任务采用服务端商品快照；指定订单只进入对应成员的「邀请我的」，不进入公共大厅。
5. 接单页分为「公共单」和「私有单」：公共单展示未指定成员的待接订单；私有单展示购买本人商品并指定本人接单的已付款待接邀请。游戏和组队/护航类型统一在「筛选」弹窗选择，支持全部游戏、全部类型，不再筛选时长或价格。接单状态开关位于「我的」，接口继续检查按游戏与服务类型入驻、在线状态、自接单及占单限制。
6. 护航负责人可在开始前添加副手，开始后锁定名单。任务完成后提交验收；组队按时长完成（演示可点击「模拟走满时长」）。下单用户确认后，系统扣除服务费并按成员份额自动结算，无需员工生成批次或登记付款。
7. 入驻流程：用户在“我的”申请 → 后台客户管理的用户行点击“查看入驻进展” → 资料审核 → 专项考核 → 录入至少 60 分后开通对应类型、游戏的商品发布与接单资格。两类独立，普通购买服务不受资格限制。
8. 普通用户在「我的」直接查看订单，不展示个人页子 tab；已入驻用户展示「我的订单 / 我的商品」，商品子页可发布、上下架个人商品。「我要入驻」统一放在下方功能菜单，弹窗内按游戏和组队/护航分别申请、查看考核进展。订单列表不再重复展示标题；售后仍支持全额／部分模拟退款，待审核时冻结履约和结算。

初始数据包含 3 款游戏（三角洲、无畏契约、英雄联盟）、10 个用户档案和 20 笔不同状态订单。体验账号覆盖四种状态：「林序」无资格、「小屿」仅组队、「凛」仅护航、「岚」两类都有；可在顶部“体验账号”切换。副手可选择「远山」。后台员工身份切换在员工卡片或头像处。

## 模拟服务约定

- 默认直接调用浏览器内的 Mock Transport，不实际发送 HTTP 请求。接口路径、请求与响应类型在共享模块统一定义。
- 品牌已统一为“诺曼部落 Norman Club”；旧品牌配置会自动迁移，不清空订单、资格或筛选记录。为兼容已有数据，主业务数据键仍为 `stellar-club:database:v1`。H5 使用 LocalStorage，同一浏览器同源标签页共享；微信小程序使用 `uni.getStorageSync/setStorageSync` 原生存储。H5、小程序和不同设备的数据各自独立，只有接入同一真实后端后才能跨端同步。
- 用户端可见时每 10 秒刷新，切后台暂停计时器，回前台刷新订单与计时；后台每 12 秒刷新，并监听跨标签页存储变化。
- 支持 Web Locks 的浏览器会串行处理同源模拟请求；这只是演示一致性机制。真实接单并发控制必须由服务端数据库事务实现。
- 数据更新失败不会自动转入真实付款。页面明确标注模拟登录、支付、退款和结算。
- Mock 登录为演示身份签发模拟会话，默认自动登录以便快速体验；HTTP 模式使用短信验证码及服务端会话，员工使用密码＋TOTP。
- Mock 的历史评分与订单数是固定档案样例。真实短信发送待签名和模板审核后配置；图片上传、在线客服及实际支付渠道尚未接入。
- 为方便演示，下单用户确认完成后立即自动记录模拟结算，**未实现真实业务的售后等待期、税务处理、银行付款与渠道对账**。
- 结算后退款需真实后台另行设计结算调整流程，当前演示对此入口作限制。

## H5 与微信小程序

复制对应应用 `.env.example` 为 `.env.local`，设置 `VITE_API_MODE=http` 和 API 地址即可改用 HTTP Transport。真实 HTTP 模式已使用短信登录 / 员工密码与动态码登录，服务端负责身份、权限和事务；`mock-login` 仅存在于浏览器 Demo。

H5 与小程序登录、支付需要分别接入。内部 `userId` 独立于 `appid + openid`；不能直接使用公众号 OpenID 作为小程序 OpenID。

用户端现已可分别构建 H5 和微信小程序，订单、商品、资格、护航协作、售后及钱包共用业务实现。微信端适配胶囊导航、安全区、弹窗滚动、原生存储、前后台生命周期与首页分享。默认仍是模拟账号与模拟支付。

```bash
npm run dev:mp-weixin    # 微信开发版，持续编译
npm run build:mp-weixin  # 微信发布构建 + 产物完整性/主包体积检查
npm run build:all        # H5、PC 后台和微信小程序一起构建
```

微信开发者工具导入目录：`apps/mobile/dist/build/mp-weixin`（开发模式为 `dist/dev/mp-weixin`）。没有 AppID 时生成 `touristappid` 游客模拟项目；已注册后，在 `apps/mobile/.env.local` 设置公开的 `WEIXIN_APPID=wx...` 并重新构建。不把 AppSecret、支付密钥或证书放进前端。

完整导入、联调和上线步骤见 [微信小程序说明](docs/WEIXIN.md)。已通过编译与代码/产物检查，尚未完成微信开发者工具及真机验收，也未上传微信或接入真实登录支付。

## 协作分账规则

护航净报酬 = （实付金额 − 已批准退款金额）×（1 − 下单时的平台服务费比例），向下取整到分。负责人和所有副手同权均分；无法整除到分时，按名单顺序依次补一分，确保份额之和等于净报酬且相差不超过一分。开始服务后锁定名单。用户确认完成后，系统按成员自动记录已结算份额；待审核售后暂停结算，任一份额结算后，整单不再允许发起退款，需后续真实后台处理结算调整。

现有 v1 浏览器数据会迁移保留订单、会话及结算记录。旧订单归为组队时长单；旧版已认证档案转换为两类演示资格。

商品发布与接单采用同一份对应类型、游戏的考核授权。新用户默认两类均无商品发布与接单权限；待审核、考核中、拒绝均不授予权限。通过组队考核不会开放护航权限，反之亦然。页面入口与模拟接口均校验；普通用户无需考核即可购买服务和快速邀请。

组队与护航考核互不依赖，允许任意一种先通过；未开通的另一类型仍可独立提交申请，申请中或未通过不会影响已有类型的权限。体验账号描述依据实际资格动态显示；已有浏览器数据升级时补充单资格样例，保留原订单、审核记录与会话。

当前游戏目录仅开放三角洲、无畏契约和英雄联盟。组队订单统一按小时计时；护航订单发布必须提交非空字符串任务项，样例任务与下单演示默认“100w纯带出”，可修改。旧版模拟配置中的王者荣耀、和平精英映射到三角洲，并在关联订单动态中记录转换，保留金额、状态、成员及结算记录。用户自定义任务保留。

无任一有效接单资格时，隐藏发现页“＋”与底部“接单”标签，资格申请入口保留在“我的”；取得组队或护航任一类型的有效游戏资格后显示。当前停留在接单页而资格被撤销时自动返回发现页。发现页的“＋”仅用于已有资格类型的商品发布和商品管理，不提供资格申请；主入口为快速邀请。商品数据与订单分开持久化，历史数据升级自动补充商品目录，不重置订单与结算。

用户端不设独立“报酬”标签；从“我的 → 全部订单”查看订单，参与订单显示本人净报酬与结算进度，详情包含个人份额、结算批次及模拟付款时间。“我的”统计可直接进入全部、进行中、已完成订单，切换账号或重新进入全部订单会重置旧筛选。

订单页的归属选项按有效接单资格显示：普通用户仅显示“全部订单”；有任一类型及游戏接单资格时，显示“全部订单 / 我下单的 / 我参与的 / 邀请我的”。资格撤销时自动切回全部订单，状态筛选仍可正常使用。

公共单与私有单表头的“过滤”开关控制游戏和订单类型条件是否生效，关闭不会清空条件。保存后的条件和开关状态按用户、公共单/私有单分别记录到本地；重进页面与弹窗恢复，清除条件同步写回本地。取消弹窗不保存草稿，关闭过滤时保存不会自动开启。旧版时长、价格缓存不再生效。关闭过滤仍会检查入驻游戏、服务类型和指定成员，私有单不会混入公共单；售后冻结或已被接取的订单不再展示在待接列表。H5 与微信小程序共用逻辑。

发现页使用“邀请组队 / 邀请护航”。商品代表长期在售的个人服务，可被多次下单，不因完成一单、正在服务或离线而消失。商品卡显示“在线 · 空闲 / 服务中 · 可预约 / 离线 · 可预约”，详情与下单页说明服务时间需确认；服务中或离线时仍可提交指定邀请并模拟付款，实际接单继续校验在线状态、资格和未完成订单容量。发布者主动下架或资格失效时停止新下单，原订单继续履约。

## 后台与固定交易规则

客户管理列出全部注册用户，包含尚未下单的用户；入驻申请与考核按用户归档，用户行有申请时显示进展或历史记录入口。组队与护航独立处理，管理员从进展抽屉审核资料、安排考核并录入成绩，客服与财务只读查看。成员管理仅列出取得资格的成员。旧入驻考核地址跳到客户管理，旧结算地址跳到订单，旧设置地址跳到概览。

已移除独立的报酬结算与俱乐部设置。当前服务费固定为 20%，待支付订单满 10 分钟自动关闭。历史订单保留原费率与价格快照。Mock 的超时关闭在请求时检查，所有资金为模拟；真实服务端通过持久化任务自动关闭到期订单，确认完成后自动记账并创建待转账记录。实际收款、退款和转账需后续渠道适配器接入，当前不会报告资金已到账，详见 [服务端说明](docs/SERVER.md)。
