# 微信小程序与 H5 用户端

## 当前交付

用户端以 uni-app / Vue 3 / TypeScript 共用页面、状态和接口，分别编译为 H5 和微信原生小程序；员工 PC 后台保持独立。微信端不是用 web-view 包装 H5。

无任一有效接单资格时，两端均隐藏首页“＋”与“接单”标签，申请资格保留在“我的”。取得任一类型有效游戏资格后显示入口，“＋”菜单仅提供对应类型商品发布与商品管理，不提供资格申请；资格撤销时，接单页自动返回发现页。

用户端取消独立“报酬”标签，个人净报酬及结算状态并入“我的 → 全部订单”的参与订单和订单详情。

两端保留相同业务：三角洲、无畏契约、英雄联盟；组队按时长、护航按任务；快速下单不要求考核；商品发布、接单校验各自类型和游戏资格；公共单抢单、指定邀请、护航副手、均分、验收与售后。

已处理原生胶囊导航的占位、底部安全区、弹窗滚动和输入框、前后台暂停/恢复轮询及计时、首页分享、原生数据缓存。Mock 的查询解析、上海时区和金额格式不依赖小程序可能缺失的浏览器 URL / Intl。

当前为**模拟版**：登录、支付、退款、结算均不连接微信真实业务。编译与产物检查通过不等于开发者工具/真机验收通过，也不等于已上传、审核或上线。

## 构建与导入

在项目根目录执行：

```bash
npm ci
npm run check
npm test
npm run build:all
```

| 目标 | 输出目录 | 使用方式 |
| --- | --- | --- |
| 用户 H5 | `dist/mobile` | 浏览器访问或静态托管 |
| 员工后台 | `dist/admin` | PC 浏览器访问或静态托管 |
| 微信小程序 | `apps/mobile/dist/build/mp-weixin` | 微信开发者工具导入该目录 |

导入微信项目时，选择“小程序”，项目目录选**编译产物目录**，其中直接包含 `app.json` 和 `project.config.json`，不要选择仓库根目录。没有 AppID 时构建为 `touristappid`，可先用开发者工具游客模式检查本地模拟流程；游客项目不能当成可分享给朋友的体验版或发布版。

开发期间执行 `npm run dev:mp-weixin`，导入 `apps/mobile/dist/dev/mp-weixin`，保持命令运行。修改页面后由 uni-app 持续生成原生文件。

## 配置自己的小程序

复制 `apps/mobile/.env.example` 为 `apps/mobile/.env.local`，设置：

```dotenv
VITE_API_MODE=mock
VITE_API_BASE_URL=
WEIXIN_APPID=wx这里填写实际公开AppID
```

`WEIXIN_APPID` 是微信小程序的公开 AppID，格式为 wx 加 16 个十六进制字符。这里的示例文字必须替换为真实值。留空使用游客模拟项目；也可通过构建进程环境变量传入。构建会生成忽略入库的 `src/project.config.json`，再输出微信工具配置，不修改已跟踪的 manifest，也不提交账号配置。不要编辑构建产物来代替环境配置，下次构建会覆盖。

uni-app 的 DCloud AppID 与微信 AppID 是两个标识；当前工程未使用 DCloud 云服务。控制台的 DCloud AppID 提示不等于微信编译失败。

获得真实 AppID 并不自动开通真实微信登录或收款。个体工商户执照已准备好，后续可在微信公众平台完成对应小程序账号、主体及业务配置，再执行体验版上传与成员授权。

## 数据与后端边界

- H5 用浏览器 LocalStorage，微信用小程序同步缓存 API。两端模拟数据各自独立，不能从 PC 后台操作浏览器数据来审核小程序中的申请。
- 模拟账号覆盖无资格、仅组队、仅护航和双资格；未通过考核的账号仍能购买服务。
- 小程序界面会标注模拟模式；支付页只提供“确认模拟支付”。不会调用真实支付接口。
- 真实联调时，H5、小程序和后台连接同一个持久化业务后端、使用同一个内部 userId。不同微信应用的 openid 不能直接混用，跨端绑定需由服务端完成。
- HTTP 模式仅有网络适配器，**不是可上线后端**。不能只切换 `VITE_API_MODE=http` 就用于生产：登录、支付和权限仍须对接真实服务。
- 小程序 HTTP 使用 POST + `X-HTTP-Method-Override: PATCH` 执行商品上下架等更新，后端须支持该契约；详情见 `API.md`。

## 真实微信接入顺序

1. 使用实际小程序 AppID 重新构建，在微信开发者工具检查基础页面和真机布局。
2. 配置业务服务端及 HTTPS API 地址，在微信后台配置对应网络域名。保留域名校验，不通过关闭校验替代生产配置。
3. 实现小程序 `uni.login` 获取临时 code，再由后端与微信交换身份并签发业务会话；AppSecret 留在后端。H5 的微信登录使用适合其运行环境的独立流程。
4. 后端接入微信支付：创建交易、下发小程序支付参数、验签支付通知、查单、幂等和退款。客户端调起后再查询后端交易状态，不能仅凭客户端回调标记付款。
5. 完成平台要求的主体、业务类目、隐私声明、备案与审核配置；实际可选类目及材料以小程序管理后台为准，再上传体验版、真机联调并提交审核。

H5 与微信小程序的登录和支付渠道需分别配置，业务订单及资格规则继续共用。

## 验收清单

当前自动检查：业务及平台测试；H5/后台类型检查；三端生产编译；小程序组件引用完整性、AppID 格式、域名校验、主题及主包体积检查。没有安装或登录微信开发者工具时，不宣称已经完成以下原生验收：

| 检查项 | 预期 |
| --- | --- |
| iOS / Android 顶部和底部 | 不遮挡胶囊、状态栏、底部手势区 |
| 商品 / 下单 / 申请弹窗 | 可滚动到底，输入时能操作提交和关闭 |
| 前后台切换 | 后台停止定时器，返回重新取订单与计算剩余时长 |
| 资格与两类订单 | 购买无需资格，发布与接单按类型和游戏校验 |
| 原生数据持久化 | 关闭重开后保留同一小程序模拟订单与会话 |
| 首页分享 | 打开 `/pages/index/index`，不携带会话或私密订单信息 |
| 真实服务接入后 | 跨端同一账户一致、抢单互斥、回调幂等、售后及分账一致 |

## 工程说明

工作区依赖由 npm 提升到仓库根目录，uni 的微信组件路径编译无法直接处理该相对层级。Vite 在每次启动时从已锁定的 uni-ui 包复制实际使用的 `uni-icons`、`uni-number-box` 到忽略入库的 `src/components/vendor-ui`，再经 `@club-ui` 别名编译。没有修改 node_modules，不需要手工复制，也没有维护另一套组件源码。

参考：[自定义导航胶囊](https://uniapp.dcloud.net.cn/api/ui/menuButton.html)、[窗口及安全区信息](https://uniapp.dcloud.net.cn/api/system/info.html)、[跨端样式](https://zh.uniapp.dcloud.io/tutorial/syntax-css.html)、[网络方法支持表](https://uniapp.dcloud.net.cn/api/request/request.html)。

公共单筛选与 H5 共用实现：组队支持 1～8 小时时长范围及净报酬价格范围；护航只显示团队净报酬价格范围。两类筛选独立，空值不限；表头右侧打开，确认后保存条件；过滤开关开启时应用，取消不改变结果。接单状态开关在“我的”。

公共单表头“筛选”左侧提供“过滤”开关，关闭仅暂停范围过滤。确认保存的条件、开关状态通过 uni 本地存储按账号和服务类型恢复；关闭后修改并保存条件不会自动开启。取消弹窗不保存草稿。
